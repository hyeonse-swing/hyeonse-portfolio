## 오류가 곧 테스트는 아니에요

[Error to Test](/about/#error-to-test)는 Browser Error Log 내보내기, 직접 붙여 넣은 오류와 JSONL을 읽어 회귀 테스트 후보로 정리하는 로컬 도구예요. 같은 오류 메시지가 여러 번 나타났다는 사실만으로 재현 조건이나 올바른 기대 동작을 알 수는 없습니다. 이 도구의 첫 판단은 실행 스크립트를 바로 만드는 대신, 원본에서 확인 가능한 내용과 사람이 답해야 할 질문을 나누는 것입니다.

여러 입력 파일을 함께 읽을 때는 각 원본의 바이트 해시와 순서를 기록하고, 중복 ID 충돌이나 부분 입력을 검사합니다. 오류를 서명별로 묶은 다음 검토 보고서와 Flow QA 스위트 후보로 옮겨요. 재현 준비나 기대 결과의 출처가 빠져 있다면 실행을 막고 질문을 남깁니다. 검토자가 정보를 보충한 뒤 다시 분석해야 실행 가능 상태가 됩니다. 이것이 후보를 만드는 단계와 브라우저에서 실제로 확인하는 단계를 분리하는 이유예요.

## 두 묶음의 차이를 읽는 법

이전 분석 번들과 현재 입력의 서명을 비교하면 이번 입력에만 나타난 항목을 찾을 수 있어요. 하지만 이전 묶음에만 있던 서명이 이번에 보이지 않는다고 수정됐다는 뜻은 아닙니다. 두 입력의 수집 기간이나 범위가 다를 수 있고 부분 내보내기일 수도 있어요. 비교 결과에는 그런 수집 범위 경고를 함께 남겨, ‘이번 입력에서 관찰되지 않음’을 ‘문제가 해결됨’으로 바꾸지 않습니다.

Flow QA 실행 결과를 가져올 때도 원본과의 연결을 검사합니다. 분석 번들과 보고서의 스위트 해시, 케이스 ID를 대조한 뒤 오류 묶음별 결과를 보여줘요. 같은 표시 이름을 쓰는 웹·모바일 대상이 있을 수 있으므로 v0.3.0에서는 정규화된 실제 대상 식별값에서 SHA-256 지문을 만들어 대상별 최신 실행과 실패 판정을 구분합니다. 지문이 없는 예전 보고서나 대상 정보가 없는 보고서는 읽을 수 있지만 특정 대상의 결과로 합치지 않아요. 선택 실행에서 빠진 케이스도 이전의 통과 기록으로 채우지 않습니다.

## 공개 검증 기록의 의미

공개 v0.3.0 기록에는 로컬 테스트 203개, 타입 검사, 빌드, 격리 설치 패키지 검사가 적혀 있습니다. 별도로 2026년 10월의 통제된 Chromium 통합 기록이 있어요. 모두 이 글을 쓰면서 다시 실행한 검사는 아닙니다. 실제 서비스 인증과 기기 환경에서 같은 흐름이 동작하는지까지 입증한 기록도 아니에요.

대상 지문은 실행 결과를 구분하기 위한 식별값이지 익명화 수단이 아닙니다. 원본 오류의 민감 정보와 실행 환경은 도구를 쓰는 쪽에서 검토해야 합니다. 이 도구가 제공하는 결과는 검토할 후보와 확인된 실행 범위이며, 오류의 수정 완료 판정은 별도의 증거가 필요해요.
