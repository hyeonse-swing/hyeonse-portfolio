## 캡처 결과가 다른 화면에 나타날 때

[HoverShot](/about/#personal-projects)은 영역·창·시간 지연 캡처를 다른 앱 위의 떠 있는 창으로 보여주는 macOS 메뉴 막대 앱입니다. 캡처 화면에 주석을 달거나 OCR로 라이브러리를 검색할 수 있고, 영역·창 녹화를 자르거나 GIF로 내보낼 수도 있습니다. 떠 있는 창은 투명도와 클릭 통과 여부를 사용자가 조절하며, 이동한 위치와 창 상태를 저장합니다.

이런 도구에서는 어떤 이미지를 캡처했는지와 함께 결과 창이 어디에 나타나는지도 중요합니다. 여러 모니터를 연결한 환경에서 특정 화면을 캡처했는데 창이 다른 모니터에 나타나면 다시 찾아 옮겨야 합니다. 공개 v0.2.2 릴리스는 v0.2.1에서 영역·창 캡처 결과의 대상 화면 위치를 계산했어도, 실제 AppKit 창을 만드는 과정에서 표시 위치가 달라지는 문제를 다룹니다. 사용자가 옮긴 창을 다시 표시할 때 위치가 유지되는지도 같은 경로에서 확인했습니다.

## 좌표 계산과 창 생성 순서

수정의 핵심은 화면별 좌표를 단순히 다시 계산하는 데 있지 않습니다. 먼저 전체 화면 좌표계에서 캡처 결과가 놓여야 할 위치를 정합니다. 그다음 AppKit 패널을 만들고 설정을 마친 뒤, 의도한 전역 좌표를 다시 적용합니다. 패널 생성 중 AppKit이 위치를 바꿀 수 있으므로, 최종 표시 단계에서 위치를 한 번 더 맞추는 순서가 필요했습니다.

이 방식은 캡처 결과 창과 이미 이동했던 창에 같은 원칙을 적용합니다. 새 결과는 캡처한 모니터를 기준으로 놓고, 다시 여는 창은 사용자가 저장한 위치를 따릅니다. 떠 있는 창의 투명도와 클릭 통과 같은 선택은 그대로 사용자가 결정합니다. 위치 복원은 그 설정을 대신하는 자동 배치 기능이 아니라, 선택한 작업 화면의 맥락을 이어 주는 동작입니다.

## 확인한 동작과 남은 범위

릴리스 기록은 수정 전에 연결된 모니터 3대 중 외부 모니터에서 실제 AppKit 창 생성·표시 검사가 실패한 상황을 재현했다고 적습니다. 수정 뒤에는 연결된 모니터 3대에 여러 결과 창을 띄워 대상 화면을 유지하는지 확인했고, 창을 옮겼다가 다시 표시하는 검사와 기존 회귀 검사를 포함해 테스트 25개를 통과했습니다. Release 빌드, 앱 서명과 ZIP 무결성 검사도 기록돼 있습니다. 이 글을 쓰면서 해당 검사를 다시 실행한 결과는 아닙니다.

창 표시 검사는 합성 이미지를 사용했습니다. 따라서 사용자 환경의 실제 화면 캡처와 macOS 권한 요청 흐름 전체가 검증됐다고 볼 수 없습니다. 공개 ZIP은 Apple Silicon·macOS 14 이상을 대상으로 하고, 화면 녹화는 macOS 15 이상이 필요합니다. 로컬 개발 서명으로 패키징한 Apple 미공증 빌드이므로 설치 시 이 상태를 확인해야 합니다.
