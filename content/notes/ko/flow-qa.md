## 문서와 실행 사이에 필요한 검토

[Flow QA](/about/#flow-qa)는 사용자 플로우를 검토 가능한 케이스로 만들고 브라우저 실행 결과를 보고서로 남기는 로컬 도구예요. 플로우 설명에 버튼을 누르는 순서가 있어도, 무엇이 성공인지와 어느 조건에서 확인해야 하는지는 빠져 있을 수 있습니다. 그런 설명을 바로 자동 실행하면 테스트가 통과해도 실제 기대 동작을 확인했는지 판단하기 어려워요.

그래서 플로우 계획과 실행을 분리했습니다. 원본 플로우의 해시를 보존하고, 케이스의 단계가 허용된 동작인지와 assertion이 명시됐는지 확인합니다. 아직 답이 없는 질문은 실행 가능한 기대값인 것처럼 바꾸지 않고 해당 케이스를 막아요. 고정 단계는 모델 없이 실행할 수 있으며, 실제 브라우저 실행은 `tester-army/e2e`에 맡깁니다. Flow QA의 역할은 입력과 기대를 검토하고 실행 결과를 읽을 수 있는 형태로 묶는 데 있습니다.

## 선택 실행을 전체 성공으로 오해하지 않기

모든 케이스를 항상 다시 돌릴 필요는 없습니다. Flow QA는 선택한 케이스만 실행하거나, 실패·오류 케이스를 다시 실행할 준비를 할 수 있어요. 이때 전체 스위트의 식별값과 이번에 선택한 범위를 함께 보존합니다. 실행되지 않은 케이스는 통과한 케이스가 아닙니다. 두 실행을 비교할 때도 빠진 항목을 이전 실행의 통과로 채우지 않아요.

보고서는 케이스별 시도와 증거를 연결해 보여줍니다. 저장된 실행을 찾고 보고서 안의 케이스를 검색할 수 있으며, 두 번 이상 시도한 케이스만 걸러 볼 수도 있어요. 현재 화면의 필터에 남은 케이스 ID를 내려받는 기능은 검토 대상을 인계할 때 유용합니다. 내려받은 목록은 현재 보이는 항목의 목록이며 전체 Markdown·JSON 보고서가 줄어든다는 뜻은 아니에요.

## 로컬 UI가 저장하지 못한 설정

화면 설정은 브라우저 저장소를 읽거나 쓰지 못할 수 있습니다. 이 경우 현재 탭에서는 선택을 적용하되, 저장되지 않았다는 안내를 표시해요. 이후 저장에 성공하거나 설정을 초기화하면 안내가 사라집니다. 일시적으로 바뀐 화면을 다음 방문에도 유지되는 설정으로 착각하지 않게 하려는 동작입니다.

공개 v0.8.9 기록은 로컬 테스트 118개, UI 검사 8개, 새 설치 패키지 검사와 브라우저 케이스 7개의 통과를 적고 있어요. 저장소 실패와 복구는 브라우저 fixture에서 확인했습니다. 이는 공개된 과거 검증 기록이며, 이 글을 쓰면서 재실행한 결과는 아닙니다. 실제 서비스 인증, iOS·Android 기기, 브라우저 정책이나 권한에 따른 동작은 별도의 확인이 필요해요.
